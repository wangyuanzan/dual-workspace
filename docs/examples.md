# 三种项目里的用法

以下是示意，实际安排应服从项目用途、已有约定和固定路径。按需要建立分类，避免创建空目录。

## 论文与计算

```text
项目/
├─ AGENTS.md
├─ 我的工作台/
│  ├─ 论文正文.md       ← 唯一主稿
│  ├─ 结果表.csv
│  └─ 结果说明.md
└─ AI工作区/
   ├─ 计算脚本.py
   ├─ 输入数据.csv
   └─ 来源记录.md
```

用户直接修改主稿。输入变化但结果未更新时，工作台明确提示“过期、待重算”。用户仅问“怎么算的”时，解释对应公式和输入，保留正文原文；编辑正文和重新计算分别检查已有授权。

## 已有软件项目

```text
项目/
├─ package.json        ← 保持原位
├─ src/                ← 保持原位
├─ docs/使用说明.md     ← 既有主稿
├─ 我的工作台/
│  ├─ 从这里开始.md     ← 产品入口与主稿链接
│  └─ 验收结果.md
└─ AI工作区/
```

工作台链接原位主稿，不制造第二份“最新版”。没有可用产品页面时如实说明；命令成功退出不代表产品能用。如果同层规则由 `AGENTS.override.md` 生效，应更新正确入口，并保留已有约定。

## 代码学习项目

```text
项目/
├─ AGENTS.md
├─ 我的工作台/
│  ├─ 最小模型.mo      ← 用户亲自编辑的主版本
│  └─ 模型说明.md
└─ AI工作区/           ← 临时试验与验证材料
```

用户要亲自阅读和修改的代码属于工作台材料。AI 基于当前文件继续工作，保护人工修改。尚无模型时，先记录已知约定，等材料出现后再分类。

## 再次进入项目

目标和用途不变时，读取已有约定并检查必要材料即可。再次调用不应生成新的工作台、重复规则或竞争主版本。讨论可以继续深入，一次性问答无需另存文件。
