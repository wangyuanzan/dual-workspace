# 验证与限制

## 已进行的验证

开发阶段使用人工构造的隔离样本，没有把真实业务项目作为公开示例。

| 场景 | 已观察到的行为 |
|---|---|
| 已有软件项目 | 保留固定路径和说明主稿；在有效规则入口保存约定；工作台指向实际材料 |
| 科研结果变化 | 识别旧结果和当前输入差异；说明待重算；修订后复验保留正文原文 |
| 再次启用 | 原有文件内容不变，没有新增重复业务文件 |
| 新学习项目 | 将用户亲自编辑的代码纳入工作台；未预建空课程分类 |

当时自动核对覆盖 19 项文件/格式条件和 33 个本地材料链接。这是有限开发验证，不能证明任何模型都将正确执行全部指令；不是跨环境认证或持续运行的 CI 成绩。

曾发现模型仅为插入过期状态而修改论文，因此明确了“仅整理或解释时保留正文原文，把状态放在入口或针对性说明中”，并重新验证。

## 在自己的环境复核

在可丢弃的项目副本中，记录运行前后的文件差异：

1. 首次适配：确认固定路径保留、实际材料可找到、规则入口有效。
2. 主稿保护：手动修改主稿，再要求整理或解释，确认原文和人工内容受到保护。
3. 过期结果：更新输入而不更新结果，确认工作台能看见过期状态。
4. 再次调用：用途不变再次启用，确认没有重复目录、规则或竞争主版本。
5. 用途改变：说明开始学习或编辑代码，确认仅调整相关材料。
6. 能力和讨论边界：只讨论时不写文件；无法访问文件时不声称保存；普通问答不改造目录。

行为验收需要检查真实文件，不能仅搜索固定措辞。

## 已知限制

- 自动匹配取决于宿主和模型；首次启用推荐明确调用。
- 文件已安装、会话已加载、项目规则已生效，是不同的检查。
- 没有访问隔离、自动同步或后台监控；新鲜度依赖执行任务时检查来源。
- 路径、规则发现顺序和可用操作取决于宿主；当前主要围绕 Codex 编写。
- 需要文件访问和相应授权才能实际整理；只有聊天能力时仅能讨论安排。
- 示例计算用于测试协作行为，不构成科学模型验证。
