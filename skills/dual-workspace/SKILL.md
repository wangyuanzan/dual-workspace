# 人机双空间

让用户能在工作台直接阅读、审阅、修改、使用材料和作出决定；AI 负责组织执行过程与来源。根据项目用途选择具体做法，保留用户对讨论和计划深度的选择。

## 先识别当前情形

| 情形 | 行动 |
|---|---|
| 首次启用 | 了解必要上下文，提出并执行授权范围内的项目适配，保存项目约定 |
| 已有约定，继续任务或阶段交付 | 读取约定，按它维护材料；无需重新初始化 |
| 目标、用户用途或交付结构变化 | 对照已有约定更新受影响部分，保留仍然适用的内容 |
| 用户追问依据 | 定位对应材料并解释；只在需要长期使用或用户要求时保存说明 |
| 仅讨论方案 | 在对话中给出安排，等待执行指令；不写入规则或搬动文件 |

先读现有项目约定、相关目录及足够理解任务的代表材料，避免全项目无差别扫描。以用户当前说明为准，分清已知事实和暂定判断；只有无法从现有信息推断、且会实质改变安排的问题才需要澄清。

## 首次适配与项目约定

识别：项目目标；用户实际要读、改、审、用什么；现有主版本及生成关系；工具要求保留的路径。新项目先依据已知目标作最小安排，材料出现时再建立分类。

默认使用“我的工作台”和“AI工作区”。已有同等用途的空间优先沿用；中文名称、浅层分类和清楚的使用状态优先，具体名称服从用户偏好。工程固定文件及依赖可以留在原位，根目录无需只剩两个目录。

把适配结果简短并入项目**实际生效**的规则入口，保留原有内容。Codex 中检查适用的 `AGENTS.md` / `AGENTS.override.md` 及其作用范围；有 override 时不要只修改被遮蔽的同层 AGENTS.md。其他环境使用其支持的项目指令入口。无法验证加载时说明，不把普通说明文件自动当成已生效的规则。

一个“人机双空间”小节通常足够，记录确有需要的这些约定：

- 用户用途、工作台与 AI 工作区的实际位置，以及保留原位的路径。
- 主要材料的权威位置、可编辑主稿与派生成品的关系。
- 图表、结果的来源和生成方式；如何让待审、未验证或过期状态在用户入口可见。
- 阶段交付时如何整理材料；何种项目变化需要重新适配。

已有该小节则就地维护，不追加重复版本。规则中保存稳定做法，当前进度和一次性记录留在实际材料或现有记录中。项目专用约定不应依赖只有本次对话才能理解的上下文。

简要说明布置理由后继续已获授权的创建、编辑和合并。搬移、重命名、删除或覆盖已有文件前，检查用户授权：已有明确授权则按范围执行；超出范围时列明具体文件、影响和替代办法，只询问缺少的授权。未决操作不妨碍独立且已授权的工作。

## 材料与版本

- 按用途分区：用户要学习或亲自修改的代码也属于用户材料；AI 工作区按任务需要组织代码、配置、计划、测试及中间产物。
- 工作台包含实际材料。可直接放入的新材料放在这里；因固定路径、外部来源或现有主版本约束保留原位时，提供有效且标明用途的入口。不能用一页摘要代替全部成果。
- 每份可编辑材料只维护一个主版本。用户工作台里的正文可以直接是主稿；编辑前读取当前内容，保留用户修改，有冲突就指出。派生的导出件标清来源和编辑入口，避免两个可编辑“最新版”。
- 仅要求整理或解释时，保留正文主稿的原文，把必要状态与解释放在工作台的现有导航或针对性说明中。用户授权编辑正文时才修改主稿。重新计算或更改模型也分别检查已有任务授权。
- 结果对应其数据、方法或代码，并在适当位置记录足够核查的输入版本、关键参数或生成记录。依赖发生变化时，更新受影响产物，或把旧产物标为过期/待重算并在工作台显露该状态。算术正确、脚本运行成功和业务结论已验证是不同状态。

## 日常维护与交付

每完成一个有意义的阶段，读取当前材料与项目约定，把用户需要的成果整理到正确位置；检查文件、链接、主版本及来源关系。用户能直接看见待审、异常、未验证和需决定的事项。沿用现有导航，仅在确有导航需要时建立入口；无材料时不凑空分类，不为每次对话新增总结，也不把每份记录扩成长中短三个版本。

用户追问“为什么”“怎么算的”“看看代码”时，围绕该问题定位和解释，提供可用入口或适量原文；继续追问就继续深入。详细计划与讨论照常进行，不因分区而强行缩短。

通用 Skill 保存适配方法，项目约定保存具体做法。适配某个项目时不改写个人通用 Skill、全局规则或其他项目；只有用户明确要求改进通用技能时才更新母版。再次调用和技能升级时先比对现有约定，保留用户定制，仅调整有依据的差异。

交付时指出现在从哪里开始、哪些实际材料可用，以及影响使用的待办或限制。只报告已执行、已保存、已检查的事实；分别说明文件存在、指令是否被环境识别、材料是否经过验证。

例如：论文正文可以直接在“我的工作台”维护，计算脚本留在 AI 工作区；用户开始学习脚本时，提供该主版本的入口和针对性解释。输入更新但图表未重算时，工作台明确标记过期。论文的具体目录和模型约定只保存在该项目中。
